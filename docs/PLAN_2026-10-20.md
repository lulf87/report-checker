## 二、已确认的口径（用户 2026-10-20 答复）

| 问题 | 结论 |
|---|---|
| 资料能否发给大模型 | 可以 |
| 大模型使用范围 | 需要时各模式都可用，但必须做成可选；不用大模型时退回确定性流程 |
| R04 判定 | 样品描述表中的内容须与照片页标签识别结果一致；报告没有样品描述表时，不执行与样品描述表相关的检查 |

| Record 模板 | 固定，只支持现有模板 |

## 三、工作块

### A. 减轻人工复核

**A1　标签 OCR 接入 Report 自检（R02/R03/R04）**
- 从照片页抽取标签图片，用 Apple Vision 识别；大模型可选作为第二路识别。
- 解析出产品名称、型号规格、序列号/批号、生产日期、失效日期、生产企业。
- 样品描述表各字段与标签识别结果逐项比对；报告没有样品描述表时不执行。

**A2　手写识别**
- 先做不依赖大模型的改进：只渲染笔迹、按笔迹实际范围裁图、利用固定模板约束格式。
- 再加可选的大模型第三路独立读数，采用规则待确认（见第五节）。
- 符号格把整格和相邻行一起送给模型判断。

**A3　合并重复问题：** 同一原因的多条 Finding 合并显示，Ledger 仍逐条保留。例如 2795 的 9706.202 Record 24 页均未填报告编号。

**A4　复核记忆：** 文件 SHA-256、对象和证据都相同时，重跑沿用上次的人工结论。

**A5　快速复核队列：** 缩略图网格展示笔迹裁图、Report 期望值和候选值，键盘一键确认。

**A6　小项：** 补充 R07-B 接受标准的写法；9706.1 中 Report 结果为"——"的多出行判为不适用。

### B. PTR 比对（试点样本 2948、0775、1539）

- **B1　PTR 条款树：** 有文字层的用确定性解析；扫描件（5780、5782）先做 OCR；解析不确定时由大模型校正，校正结果必须能在原文中逐字找到。
- **B2　Report 侧 PTR 段落抽取：** 现有行扫描器在 PTR 表格段会错位（1539 序号 157 表 6），需按单元格几何重写。
- **B3　比对规则：**
  - 范围：第三页检验项目展开后，查缺项、多项和除外处理；
  - 条款号与标题；
  - 标准要求内容：格式差异忽略，数值、单位、公差、比较符差异由程序判定，其余措辞差异由大模型判定，不确定转人工；
  - 表格展开；
  - 引用标准的序号范围；
  - 依据、结论中的产品名称。
- **B4　大模型接入层：**
  - 供应商（OpenAI 兼容接口、Anthropic）、Base URL、模型、Key、超时、并发均可配置，带测试连接；
  - Key 只存在本机；
  - 调用按"输入哈希 + 提示词版本 + 模型"缓存，并留审计记录；
  - 输出用 JSON 结构，引用原文必须校验；
  - 大模型不能推翻程序判定的数值差异；
  - 可整体关闭。
- **B5　验收：** 在 3 份试点样本上，真实问题不漏优先、误报其次，达标后才启用 `report_ptr`。

### C. Report 自检新增审核问题统计表内容

| 分类 | 内容 | 状态 |
|---|---|---|
| 只靠 Report 可查 | 检验项目、检验结论、检验依据、封面版本、到样日期、页码、页眉、样品编号、报告编号、职务 | **已完成**：REPORT-R12～R16 |
| 依赖标签 OCR | 生产单位、产品编号/批号、样品名称、型号规格与照片页一致 | **已完成**：REPORT-R17（本机 OCR） |
| 需要合同或抽样单 | 抽样日期、委托方/地址/受检单位、量词、检验类别、抽样基数 | 只做内部一致性（R16 已包含送样/抽样字段一致性） |

## 五、已定与待定

- **手写数值采用规则（已定 (a)）：** 三路读数（Apple Vision、Tesseract、大模型）中至少两路一致才自动采用。
- **大模型供应商（待定）：** 用户尚未决定，B4 暂缓。
- **本机 OCR 不适合做手写第三路（2026-10-20 实测）：** 在 2948 的 9706.1 手写数值上，用只含笔迹的干净图片试了 RapidOCR 和 Tesseract，读数大量错误，而且两者会一致读错（如手写“309.6”两路都读成“209.6”），按“两路一致”会被错误采用。因此手写识别第三路只考虑大模型或按检验员笔迹训练的专用模型。

## 七、已完成：照片 OCR 与 R02～R04、R17、R07-B（2026-10-20）

**照片页文字识别**
- 新增 `mvp/photo_ocr.py`：Mac 上用 Apple Vision；所有平台可用 RapidOCR，已加入 `pyproject.toml` 依赖，Mac 上需执行一次 `uv sync`。两个引擎都在时各读一遍，作为两路读数。
- 识别结果写入运行目录的 `artifacts/photo-ocr.json`。环境变量 `REPORT_PHOTO_OCR=off` 可关闭。

**判定口径**
- 报告值（忽略排版空白、全/半角）在照片识别文字中找到 → 一致。
- 序列号/批号、日期两路读出同一个不同值 → 不一致；其余差异 → 人工，并列出候选值。
- 样品描述表没有该列、单元格为空或报告没有样品描述表 → 不执行。
- 报告填“/” → 标签上也没有该字段值才算一致。
- 备注不比对。

**新增 REPORT-R17：** 首页样品名称、型号规格、产品编号/批号、生产日期、生产单位、委托方及地址须能在照片页标签中找到。首页写“见…栏”时不执行；中英文并列的单位名称允许前后颠倒。

**R07-B 扩充**
- 带正负号的偏差写法：只在按绝对值理解不可能合格时才按偏差判；
- 百分比允差，含 +20%/-25% 这类不对称允差；
- SI 词头换算（MΩ↔GΩ、Hz↔kHz、ms↔μs）；
- “应小于”“不低于”“不应降到…以下”“应在X%内”“包含在A～B的频段内”；
- “0.05 (−)”这类带括号符号的结果，只在上限判定中使用。

13 份报告中 169 项待复核改为自动判定；0775 的 4 项误报（把“当设置流量＞10 L/min 时”的条件当成限值）改为通过。

## 八、已完成：支持手写被拼合的 Record（2026-10-20）

**起因：** 3944 的 9706.1 Record 用 iOS 27 导出，手写批注（Ink）为 0 条，手写只剩页面图形；同时带一层不可见的手写识别文字，表格底纹多出内缩的重复色块，原工具在第 70 页报错退出。之前能用的 Record（iOS 18/26 导出）都保留了批注。

**做法：** 新增 `mvp/record_flattened.py`。Record 没有 Ink 批注时，先在内存中整理再交给原有规则，原文件不改：
- 每个手写笔画转换为隐藏的 Ink 批注；9706.1 用笔画轮廓（判断是否勾到方框），9706.202 用还原的笔迹中线（区分 √、△、×、/）；小于 15 pt 的笔画按轮廓处理，避免文字笔画被认成“×”；
- 删除只以不可见方式出现的手写识别文字层；
- 删除与外层同色、完全内含的重复底纹（内部有手写的不删）。

**顺带修复（对正常 Record 同样有益）：**
- 第 70、94 页异体方框的另一种编码（Wingdings 2 的“£”）；
- 封面 5 条下划线也接受细填充色块；
- 4.11、9.6 的测量单元格按行文字定位，不再依赖固定行号（手写跨越表格线时行号会偏移）。

**验证（把 2948、1539 的批注拼合进页面后与原文件对比）：**

## 十、9706.202 手写识别改进（2026-10-21）

用户在 3944 的 202 结果中提出三个问题，结论和修改如下（`full_record_202.py`、`record_flattened.py` 1.3.0、工作台明细）。
