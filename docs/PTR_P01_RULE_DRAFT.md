# PTR-P01 规则冻结草案（非发布产物）

日期：2026-10-11

本文只记录审计契约和候选结构，不把 PTR↔Report 离线草案当作正式结果。当前 `report_ptr` 已按三份试点授权启用；`report_ptr_report` 组合别名仍保持 `enabled=false`，原因码为 `PTR_NOT_VALIDATED`。输入、结果和证据的接口合同由 `mvp/ptr_report_contract.py` 提供，正式结果由 `mvp.run_ptr_report` 生成。

当前另有 `mvp/ptr_compare.py` 作为离线比较层：它执行范围、条款、数值、单位、引用和覆盖层的规则核对，并输出不可发布的 Coverage Ledger；`mvp/ptr_ocr.py` 只提供扫描 PTR 的本机 OCR 观察，`mvp/ptr_llm.py` 只验证未来 LLM 的逐字证据。离线草案不能绕过正式 Runner，也不能由 LLM 单独给出通过结论。

当前 PTR-P01 的唯一规则版本为 `0.5.1-draft`。合同、比较器、能力目录、验收门和结果中的 `rule_version` 均从同一版本源生成；历史结果仍保留其生成时的版本快照。

## 2026-10-27 增量（0.5.1-draft）

布局解析器升级为 `ptr-layout-1.4`。文本严格比对不一致后，比较器会依次尝试下列“安全等价规则”。只有在去掉对应内容后两侧文本**完全相等**时才判一致，并在 `text_comparison.equivalence_rules` 中记录用到的每条规则，原始差异 `text_diff` 照常保留供界面展示：

| 规则 | 去掉的内容 | 限制条件 |
|---|---|---|
| `PTR_RUNNING_HEADER` | PTR 页眉/页脚 | 只认在 ≥40%（且至少 3）页上整行重复出现的行；不写死公司名 |
| `PTR_FIGURE_LABELS` | “图N…”图注及其前面插图内的短标签 | 标签行 ≤20 字、无句末标点、不含“应/须/表N”，遇到要求句即停止 |
| `REPORT_UNIT_LINE` | Report“单位：X”行 | X 必须在 PTR 该条文本中出现 |
| `REPORT_RESULT_LABELS` | Report 结果子行标签（X方向/Y方向、Yaw/Pitch 等） | ≥2 行、每行 ≤10 字、无数字和要求词、成组平行（同前缀/同后缀/纯字母），且位于单元格末尾或紧跟“单位：”行 |
| `PUNCTUATION_ONLY` | 标点、项目符号 | 数字间的“.”“,”保留 |
| `REPORT_REPEATED_TEXT` | Report 重复写的同一要求 | 被去掉的句子必须是前文已出现的内容 |
| `REPORT_EXPANDED_REFERENCE` | Report 展开写出的被引条款原文（如“2.5.7 a)…”） | 展开内容必须与 PTR 对应条款一致 |

**扫描件 PTR 的放行条件（`OCR_DUAL_ENGINE_MATCH`，2026-11-13 用户同意）**：扫描件 PTR 的文字来自 OCR，原先一律“待确认”。现在同时满足以下条件时判“一致”，并在 `text_comparison.equivalence_rules` 记录本规则、在 `text_comparison.ocr_confirmation` 记录参与的引擎：

1. Report 一侧来自文字层，不是 OCR；
2. 主引擎读出的条款按普通规则与 Report “一致”，且没有留给人工的表格；
3. 至少还有一个 OCR 引擎读过这份 PTR；其余**每个**引擎的读数都**各自独立分段**后，恰有一条同号条款，且它按同样的规则也与 Report “一致”；
4. 两个读数都没有分段标记以外的提取问题（重复条款号、目录与正文不符等都会阻止放行）。

任何一条不满足都保持“待确认”（`PTR_OCR_CANDIDATES_MANUAL`），`ocr_confirmation.reason` 写明卡在哪一条。本规则只能给出“一致”；OCR 读出的差异不会被报成“不一致”。只装了一个 OCR 引擎时本规则不生效。13 组样本中 2170、5782、5780 共 69 条由此从待确认变为一致，全部与标准答案相符（5780 另需正文定位 `ocr-section-1.2` 识别以点结尾的条款号）；2170 的 2.1.1.11.2 主引擎读数一致而第二引擎读出数值不同，保持待确认。

**一个条款对应多行表格（`TABLE_ROW_EXPANSION` 的多行情形，2026-11-13）**：条款的参数在 PTR 表格里有两行以上（两个参数、同名多行、或按型号分行），Report 把每一行抄成一个“行名 + 常规数值/标准设置/允许误差”块时：

1. PTR 每个物理行是一条记录；竖向合并单元格按单元格坐标补到它覆盖的每一行（下方行在该列没有自己的单元格、且上方单元格的矩形向下覆盖到该行时才继承；首列和横向合并不继承）；首格写了两个参数名（`房室间期(ms)⏎感知后的房室间期(ms)`）时两个名字都可指向该行；
2. Report 每个块必须与某一条记录**整行相同**：每个带标签的值等于该行对应格，且该行每个非空格都被抄到（缺的格只有在 Report 结果表的标签栏里以“列名：值”出现且值相等时才算，记 `CELL_EQUAL_IN_RESULT_TABLE`）；
3. 块的集合必须恰好是应抄的行：表格没有型号列 → 全部行；有型号列 → 型号格写着 Report 第三页“型号规格”登记的型号（名称须独立成词，换行折断的名称也算）或“全部型号”的那些行（2026-11-13 用户裁定：只抄送检型号的行且数值相同 → 一致）；第三页没写明型号（如“见样品描述栏”）时只有抄全所有行才通过。

任何一条不满足都保持待确认（`TABLE_CELL_REVIEW_REQUIRED`），`row_expansion.row_coverage` 记录应抄行数、Report 块数和登记型号。另：条款标题括号里的别名（`心室后心房不应期（PVARP）`）可以指向与它完全同名的表格行；标签单独一行、值行自带格内标签（`磁频率（min−1）:` / `BOS：96min−1`）按格内标签取值。13 组中 0596 2.1.4.2、3940 2.1.7/2.1.11/2.1.12、4788 2.1.10 由此从待确认变为一致，均与标准答案相符。

**表格核对的其他补充（2026-11-13）**：

- **单行展开也只认送检型号的值**（`_require_submitted_model`）：参数行按型号分列（表头 `型号 | 6131 | 6232`）或按型号分行、且各型号的值不同时，Report 的值必须是第三页登记型号的那个值；等于别的型号的值记 `CELL_OF_ANOTHER_MODEL`，第三页没写明型号记 `SUBMITTED_MODEL_UNKNOWN`，都保持待确认。各型号值相同的格不受影响。被分页截断的型号格（`Alpha 8 DR` / 下一页 `Alpha 8⏎DR-T`）先拼成一格。13 组样本判定无变化。
- **参数列表格**（`compare_parameter_column`）：PTR 表格有一列的列名就是条款的参数（`腔室 | 模式 | 感知不应期`），Report 把这一列抄成“行名：值”（`心室：95 ms ±10 ms`）。每个 PTR 行必须恰有一行同名的 Report 行且值相等；数字不同判不一致，缺行、重复行待确认。其余列（如“模式”）不要求 Report 抄写（用户对 0596 2.1.6.1 的确认），记在 `row_expansion.unchecked_ptr_columns`；带型号列的表格不走这条。
- **跨页断行**：续表第一行的首格只有括号单位（`（ms）`）、没有新的行名时，是上一页最后一行的后半截，两段拼起来再比（4788 2.1.8）。
- **两侧都印表格**（`compare_table_cells`）同样按单元格坐标继承竖向合并单元格（5332 2.1.3 的“≥15”管四行）。
- **只指向附录**（`APPENDIX_REFERENCED_BY_NAME_ONLY`）：两侧文字一致、数值一致、引用的都只是同一个“附录X”、两侧都没有表格内容时判一致。不适用于“表N”：两侧都提取不到的表格可能两侧都是图片，仍待确认。
- **单位行里的指数不是数值**：Report 的 `单位：min−1`、`单位：mm2` 这类行不参与数值比较（单位本身仍由单位规则核对）。

**措辞差异一律不等价**（2026-11-08 用户裁定）：即使意思不变，删“等”/“应”、“动作时候”/“动作时”、“机械臂(USM)”简写成“USM”、图题少字都不放行。原 `ACTION_TIME_WORDING` 规则已删除。

**个别字不同直接判不一致（`TEXT_WORDING_MISMATCH`）**：安全等价规则都不适用时，若两侧（均非 OCR）规整后文字的每处差异去掉标点和括号后都只是汉字、且每处每侧不超过 4 个字，并且数字、单位、引用都一致，则判“不一致”，差异记在 `text_comparison.wording_differences`。例：删“等”/“应”、“动作时候”/“动作时”、“机械臂(USM)”→“USM”、“材质为”→“材质力”、“转向自如”→“转向白如”。差异含数字、字母或符号（如结果标签“±X方向”）、或超过 4 个字（挪动、补充说明、图题大段缺失）仍为待确认（`TEXT_REVIEW_REQUIRED`）。

**该报不一致却停在待确认的三种情况（2026-11-14）**：以下三条只把“待确认”改判“不一致”或去掉干扰行，不会把任何结果改成“一致”以外的更宽松判定，也都不用于 OCR 文本。

- **图题不同（`FIGURE_CAPTION_MISMATCH`）**：两侧都写了同一编号的图题（PTR `图1 XX MODE 3 预设输出波形图`，Report `图1 XX输出波形图` 或 `图1 是XX输出波形图。`），去标点后不相同，且任一侧都不是另一侧的开头（开头相同可能只是图题换行，仍待确认）。差异记在 `text_comparison.figure_caption_differences`。只在文字本来要判 `TEXT_REVIEW_REQUIRED` 时生效（1539 2.2.2）。
- **表格单元格只差一两个字符（`CELL_FEW_CHARACTERS_DIFFERENT`）**：Report 按“列名：值”抄 PTR 表格行，值与最接近的 PTR 单元格相比，增、删、改的字符两侧各不超过 2 个，且两侧都不少于 12 个字符。这说明抄的就是这一格，但没有照抄（0596 2.1.1：PTR `0Dplus/DDIR`，Report `Dplus/DDIR`）。短单元格（一个数值、一个单位）不适用，仍按原规则。
- **照抄的表格注释（`REPORT_TABLE_NOTE_COPIED`）**：PTR 在表格后以 `[行名]说明…` 的形式写注释；Report 在该行的展开内容里照抄了同名注释，且逐字相同（可跨行）时，这几行不参加正文比较，并记入 `text_comparison.equivalence_rules` 和 `report_table_note_lines`。注释有任何不同、或标签不是本行行名，都不去掉。去掉后其余文字照常比较（4788 2.1.11 因此由“差异太多”变为只差一个“应”，判 `TEXT_WORDING_MISMATCH`）。

**减少文字版待确认（2026-11-14 续）**：

- **报告表格的型号编号作行名（`rows_keyed_by_model_number`）**：Report“标准要求”栏里单独一格的 5～8 位数字，原先一律当作样品结果标签删掉；在按型号分行的表格里它是行名（`型号 | 名称 | 夹持力`）。现在把它按列另存（`model_number_cells`），比较时先带着型号编号逐格核对一次，**只有整条完全核对一致才采用**，否则按原来（不带型号）的方式比较。因此它只能放行、不能报不一致（0778 2.1.3、2.1.15）。Report 省略了列、只列送检型号或把一张表拆成几张的，仍待确认。
- **圈号脚注（`REPORT_TABLE_NOTE_COPIED`）**：PTR 表格行名带 `①` 等圈号、表后有同号脚注；Report 在该行下逐字照抄该脚注时，这几行不参加正文比较（3940 2.1.9）。圈号必须出现在该行的 PTR 行名里。
- **单个结果标签（`REPORT_RESULT_LABELS`）**：Report 要求格末尾单独一行的结果标签（`±X 方向：`，其后至多一行 `单位：X`），不是 PTR 的某一行，且由 PTR 要求里的原词组成（整体出现，或拆成两段都出现）时忽略（0778 2.1.19.2.1）。
- **表格写成文字时的表号（`TABLE_VERIFIED_AS_TEXT`）**：`REPORT_TABLE_AS_TEXT` 已逐行核对了该条款的全部 PTR 表格、两侧引用同一表号时，Report 的表号即视为已绑定（4788 2.3）。
- **行名里的“的”**：按条款参数找表格行时，`感知后房室间期` 与 `感知后的房室间期` 视为同一行名；单元格仍逐格比较（3940 2.1.15）。
- **整行挪了位置（`REPORT_LINES_MOVED`，2026-11-14 用户裁定：算一致）**：Report 的文字等于 PTR 的文字把**一段连续的整行**原样移到另一处，去标点后逐字相同，没有任何增、删、改（4788 2.8.2：两行尺寸要求从图前挪到图后）。只挪半句、挪了又改了字、或少了一行，都不适用。比较时保留两侧的图题；带图的条款里 PTR 图内不超过 4 个字符的标注（`A`、`B`）不参加比较；Report 的 `单位：mm` 行在 PTR 把单位写成中文（`毫米`）时同样忽略。数值、单位、引用仍各自独立核对。
- **PTR 重复条款号且不在检验范围**：PTR 同一条款号出现两次（`AMBIGUOUS_PTR_MAPPING`），但该条款不在检验范围、Report 也没有这一条时，按不检条款排除（4788 2.2.4）。在检验范围内或 Report 有该条款的仍待确认。

### 解析误报修正（2026-11-08，对照标准答案的 18 条误报）

- **条款号与字母分格**：Report 标准条款格写成“2.3.4.3⏎c)”或长号折行“2.3.13.1⏎2 a)”时识别为 `2.3.4.3c`/`2.3.13.12a`（`ptr_layout.report_clause_cell`）。此前这些条款被误报为 `REPORT_CLAUSE_MISSING`。
- **`REPORT_PARENT_TITLE`**（安全等价）：这种单独成行的字母分项，Report 会在前面写上级条款标题（如“耐腐蚀性能”“SUTURECUT 型持针钳专用性能要求”），有时再写一次字母“b）”。只有该标题与 PTR 上级条款标题**完全相同**、去掉标题和字母后其余文字与 PTR 分项完全相同时才放行。
- **单位被空格或换行拆开**：“5M Ω”=“5MΩ”，“10μ⏎g/g”=“10μg/g”；上标丢失的科学计数“3.6×103 Pa”按 3.6×10³ Pa 读（只认 ×10 后紧跟一位指数）。
- **`UNIT_LABEL_WITHOUT_PRINTED_VALUE`**：Report 同一格有多个“单位：X”，其中有的与正文数值相符、有的在正文中找不到同量纲数值（属于表格或展开的被引条款，如角度表的“单位：°”）时，判待确认而不是单位矛盾。只有一个单位且与正文量纲不符仍是硬差异；同量纲不同倍数（MΩ/GΩ、m³/mm³）仍是硬差异。
- **表格写成文字时的数值**：所有 PTR 表格都经 `REPORT_TABLE_AS_TEXT` 逐格核对后，PTR 正文数值加表格数值与 Report 数值作为同一组比较（顺序可不同）。
- **`PARENT_TABLES_CHECKED_IN_CHILDREN`**：Report 上级条款只写标题、PTR 上级条款正文列出表题和注释时，若这些表都被其下级条款引用（在下级条款逐条核对），引用与表格按一致处理；有表未被任何下级条款引用 → 待确认（`PARENT_TABLES_NOT_CITED_BY_CHILDREN`）。

同时修正三处抽取问题：“2.85 个周期/°”类数值不再被识别为条款号；Report 中“470066：0°±3°。”这类“型号：要求”行不再被当成型号子行标签丢弃（子行标签改为通用的 5～8 位型号 + 左路/右路）；“表1：…”全角冒号题注可以被识别。

### 表格按行展开核对（`mvp/ptr_table_rows.py`）

起搏器类 PTR 把参数放在一张表里，条款只写“应符合表 N 的要求”；Report 则把对应参数行展开成“设置：…/标称值：…/允差：…”。整表指纹比不上时，比较器先做按行核对：

- 用条款标题（冒号前部分，去掉单位括号和①②脚注）在被引表中找**唯一**一行；Report 展开中必须出现该行的参数名，否则不执行（防止条款号错位时拿错行比较）。
- Report 的“标签：值”中，标签必须是 PTR 表头（或型号列表格中的参数名），值归一化后必须与该行对应单元格**完全相同**；`+20/-25%` 与 `+20%/-25%`、`± 20`（单位在参数名里）与 `±20ms` 视为相同。
- Report 把一个 PTR 单元格拆成多段（如按 240/500/2000 Ω 负载分写）时，各段按 PTR 原文界定，并且必须**按顺序拼回**完整的 PTR 单元格。
- 测试点行（`@240Ω`、`0.25V、0.5V：±0.25 V`）中的数字必须出现在 PTR 条款或表中，或落在该参数的取值范围内；负载电阻只有在 PTR 条款本身写了负载时才要求一致。
- 跨页续表（下一页顶部、列数相同、无题注）继承上一张表的标签，视为同一张表；同名题注出现多次时，优先使用所在章节（祖先条款）内的那张。
- 核对通过后，从 Report 文本中只去掉已核对的展开行及其不含数字的小标题，**剩余文本仍按文本/数值/单位规则比较**，因此展开之外的差异（如 0596 2.1.2 的 1000Ω/2000Ω）会作为硬差异报出。
- 结果写入 `table_comparison.row_expansion.cells`，每个单元格带 `status`、`reason_code`，未一致的单元格附最接近的 PTR 值与逐字差异 `diff`。

### 实体表格按行名比对

PTR 与 Report 都印出表格、但整表指纹不同（列被拆分、多了“关节编号”列、PTR 为无边框文字表）时，按“行名 → 值”比较：

- PTR 每行拆成行名和值（文字表按首个空白拆分；一格多行视为多个子行）；同名行（如表 7、表 8 都有“近红外”）按出现顺序合并。
- Report 每行中找到与 PTR 行名相同的那一格，其后各格为值；同一行名在 Report 中出现多次（如左、右 MTM 分成两张表）按顺序拼接。
- 值归一化后必须相同；数值相等但写法不同（`0.70`/`0.7`）也是硬差异，记为 `CELL_NUMBER_WRITTEN_DIFFERENTLY`（2026-11-08 用户裁定：数字须照抄 PTR）。数字不同为硬差异；PTR 行在 Report 中缺失为硬差异；Report 多出的数据行、PTR 行名不足两个字（竖排合并单元格未拆开）为人工确认。Report 表内的题注和重复表头行不参与比较，但表内题注计入 Report 的表格引用。

### 0775 剩余项的补充规则

- 无“表N”编号的 PTR 表格被 Report 逐格写成文字（`REPORT_TABLE_AS_TEXT`）：先尝试原样去除；否则逐行比较，每行字符必须完全相同（只允许同一行内折行导致的阅读顺序不同），行顺序必须一致，跨页重复印的表头行跳过。
- Report 在正文后单列重复的标准号视为重复文字。
- 两边都只按名称引用别处的表格/附录（PTR 绑定均为“引用”、Report 无表格行、引用相同，且正文和数值都一致）时，表格判为 `TABLE_REFERENCED_BY_NAME_ONLY`。
- 表格行开头的序号列（`1`、`6`、`θ1`、`d3`）不作为行名；PTR 单元格以运算符结尾（被截断）转人工。
- PTR 以正文形式排出的合并单元格表格：Report 表格行的每一格都能在 PTR 原文中找到时记为 `ROW_CELLS_IN_PTR_TEXT`。
- 表格按行名全部一致后，正文比较不再包含两侧的表题注和已在表格中出现的表格内容行；此时引用绑定视为成立。
- 同一单元格同时写出“2.2.3 …2.2.3.1 …a)”时产生的重复字母子项（2.2.3a）在 PTR 无此条款且与 2.2.3.1a 文字相同时去除。
- 题注识别支持“附录C.1”；数值提取前合并被换行打断的汉字词（“详见附\n录C.1”）。

### 2170 带来的补充（布局解析器 ptr-layout-1.5）

- 目录行（`2.1.1 压力导管……`、`……错误！未定义书签。`）不再生成条款，也不再触发“3 试验方法”停止解析。此前 2170 PTR 只读到目录里的 17 个条款，Report 的 28 条全部误报“PTR 中没有找到”。
- `附表1` 题注对应正文中的“表1”。
- “标准号 + 中附录C / 中表N”是所引标准的附录或表格，不作为本文件的表格引用。
- Report 展开写出 PTR 其他条款原文（`2.3.1.1 直流电阻 …`，不带字母项）时，需与该 PTR 条款文字一致（展开内容至少覆盖该条款 60%）才视为展开引用。
- 回归要求：以上一提交为基线逐条比较所有素材，原“一致”不得变差、原“不一致”不得消失；对比结果见提交说明。

### 无编号表格（`UNLABELLED_TABLE_BINDING_UNVERIFIED`）

PTR 条款里印有表格、但两侧都没有“表N”编号时，按题注比较的规则无法证明表格与参数/型号的对应关系，原本会“一致”的条款转为待确认（数值、单位、引用的硬差异仍优先报出）。例外——表格内容已被逐格核对时保持一致：

- 该条所有 PTR 表格都是本页实体表格，且 Report 把**每一张**都逐格写成了文字并通过 `REPORT_TABLE_AS_TEXT`（只去掉其中几张不算）：`table_comparison.reason_code = UNLABELLED_TABLE_VERIFIED_AS_TEXT`。
- 两侧都印出表格，按行名逐格比较（`TABLE_ROW_KEYS`）**全部一致**（每格都必须是按行名绑定的 `CELL_EQUAL`；只在 PTR 原文中“找得到”的 `ROW_CELLS_IN_PTR_TEXT` 不算），且去掉表格后其余正文/数值/单位/引用也全部一致：结果与有编号表格的逐格核对相同（`TABLE_CELLS_MATCH`），`table_comparison.unlabelled_table = true`。逐格比较未全部一致时不采用其结论，仍为待确认（不会因此新增“不一致”）。
- 其余情况（表格内容未核对）仍为待确认。

### 条款号错位

Report 某条的标题与 PTR 同号条款不同，却与同一父条款下另一条 PTR 的标题相同时，判为 `CLAUSE_NUMBER_SHIFTED`（硬差异），并在 `clause_shift.message` 中写明对应的 PTR 条款号。

此外，归一化补充了数学减号 `−`（U+2212）→ `-`。

## 输入与范围

- 输入角色固定为 `report` 和 `ptr`；两侧在草案中保存路径、页数、页面几何和 SHA-256。
- 正式 Run 的输入字段固定为 `report_document_id` 与 `ptr_document_id`，一对一、创建后不可替换；`record_document_id` 被明确列为禁用角色。preflight 会同时返回 `input_contract` 和按角色排列的 `input_documents`，即使 PTR 仍被阻止创建 Run。

- 当前草案不解析手写内容，不把单个 OCR 引擎的读数当作事实（两个引擎各自与 Report 一致时的放行见 `OCR_DUAL_ENGINE_MATCH`），不展开被引用表格，也不生成自动一致/不一致结论。

## 实现与验收门槛

草案提取入口为 `mvp/ptr_p01.py`，输入/结果合同入口为 `mvp/ptr_report_contract.py`，测试为 `tests/test_ptr_p01.py`。提取器仍不接入 `mvp.run_modes` 或 Worker；正式目录和 Runner 负责可发布结果，草案入口只允许生成不可发布草案。

正式启用已经完成；后续新增版式或规则版本仍需完成：

1. 选择至少 2–3 份结构显著不同的 PTR，逐条人工确认声明范围、父子条款和每个引用表格/附录的展开结果。
2. 冻结 Report 范围与 PTR RequirementGraph 的匹配键、缺项定义、范围外定义和循环引用处理。
3. 为人工确认过的缺项、额外条款、父条款缺失、中间条款缺失和引用循环建立正反测试夹具。
4. 为正式 Runner 增加有版本的 `PTR-P01`、Evidence/Artifact 清单、WorkerResult 发布校验和 UI 双文档定位测试。
5. 重新执行 preflight/create/worker/publish 全链路，并在通过后更新正式规则版本和签字记录。

草案候选观察仍不能写成正式一致/不一致结论；正式 Runner 的结果必须经过规则、证据和发布闸门校验。
