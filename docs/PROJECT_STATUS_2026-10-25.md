# 报告核对工具项目当前状态

更新时间：2026-10-25

## 一、当前状态

项目已经进入“PTR ↔ Report 规则链路可运行、正式 PTR 模式已启用、最新规则版本和人工复核仍需收口”的阶段。

当前 PTR 模式采用规则优先方式运行：

- PTR 条款要求与 Report 的接受标准进行比对；
- Report 检验结果是否满足接受标准，由 Report 自检单独检查；
- LLM 只能辅助处理规则无法判断的文本差异；
- 数值、单位、范围、引用和表格硬差异不能由 LLM 覆盖；
- `manual` 表示证据不足，需要人工确认，不表示自动通过。

## 三、已经完成的主要工作

### 3.1 核对边界

当前 PTR 模式的比较对象已经固定为：

> PTR 条款要求 ↔ Report 的接受标准

Report 中“检验结果是否满足接受标准”不直接作为 PTR-P01 的通过条件。该内容由 Report 自检中的 `REPORT-R07-B` 和 `REPORT-R07` 负责。

### 3.2 PTR 比较规则

已经完成以下规则能力：

- Report 第三页范围提取；
- PTR 条款树和父子条款识别；
- 条款正文归一化；
- 数值、单位、比较符、上下限和允差比较；
- GB/YY 标准引用比较；
- 表格和附录引用绑定；
- Coverage Ledger 覆盖审计；
- PDF 页码、坐标、原文和 SHA-256 证据保存；
- `matched / mismatch / manual / excluded` 四种结果状态；
- 无法证明一致时保留为 `manual`，不自动判为一致。

### 3.3 高优先级规则修正

- Report 中的测试条件、模式、型号、设置参数等附加内容与接受标准分离；
- 单位等价、SI 词头、复合单位和幂单位处理；
- `m³/mm³`、`MΩ/GΩ` 等倍率差异保留为硬风险；
- Report 中的裸最大值可以按上限解释；
- 精确目标、额定值、标称值和允差仍保守保留为人工项。

### 3.4 正式运行链路

已经完成：

- PTR 业务签字和验收门；
- preflight、Run、Worker、publish 链路；
- 双 PDF 证据定位；
- 源文件完整性和哈希校验；
- 启动前清理旧的本项目服务；
- PTR 模式正式能力目录启用。

### 3.5 结果页面

- 显示 Report 和 PTR 文件名；
- 显示“PTR 条款 ↔ Report 接受标准”；

## 五、剩余任务

### 5.1 统一 PTR 规则版本和验收版本

这是目前最重要的工程任务。

当前存在版本不一致：

- `mvp/ptr_report_contract.py` 仍声明 `PTR_P01_RULE_VERSION = 0.1.0-draft`；
- `mvp/ptr_compare.py` 使用 `PTR_COMPARE_RULE_VERSION = 0.5.0-draft`；
- 旧验收包使用过 `0.4.0-draft`；
- 最新正式结果使用 `0.5.0-draft`。

需要选定正式版本，统一规则合同、能力目录、验收包、结果文件和文档，然后重新跑验收门。

### 5.2 处理 0775 的 48 条待确认

需要人工确认：

- 表格是否逐行、逐列、逐项一致；
- 正文差异是否只是排版、重复或 Report 补充说明；
- 是否存在真正的新增、缺少、数值变化、单位变化、模式变化或引用变化。

人工标注结果应反过来用于改进表格映射和正文归一化规则。

### 5.3 提高复杂表格自动核对能力

跨页表格、无边框表格、合并列和附录引用仍然容易进入 `manual`。这会直接影响 0775、1539、3940、4788 等样本的人工数量。

### 5.4 接入实际的 LLM 复核供应商

当前已经有 LLM 任务格式、证据校验和边界约束，但实际运行中：

- `llm.used = false`；
- `queue_count = 0`；
- 没有实际调用模型。

后续 LLM 只能处理文本人工项，不能处理数值、单位、范围、引用和表格硬差异。

### 5.5 完善人工复核后的闭环

需要继续确认：

- 人工意见是否形成正式的 `resolved_status`；
- 导出结果是否区分机器结论和人工复核结论；
- 人工确认是否绑定具体原文证据；
- 规则版本变化后，旧人工意见是否需要重新确认。

### 5.6 同步项目文档

部分文档仍保留旧状态。例如：

- `DESIGN.md` 仍描述 `report_ptr` 为禁用；
- `docs/COMPARISON_SCOPE.md` 已描述 `report_ptr` 为启用；
- 部分验收文件仍记录旧的规则版本。

这些内容需要统一为当前实际状态。

## 六、主要风险

### 高风险

1. **规则版本、合同版本和验收包版本不一致**，可能导致结果无法准确追溯。
2. **0775 仍有 48 条人工项**，表明复杂表格和文本差异的自动处理能力仍有限。
3. **LLM 供应商尚未实际接入**，规则+LLM 目前只有接口和约束，没有实际模型复核。

### 中风险

1. PDF 表格结构复杂时，可能产生较多 `manual`，人工工作量较大；
2. OCR 不可用或识别不稳定时，无法自动通过；
3. 单位倍率差异可能是真错误，也可能是原始文件单位笔误，需要人工确认；
4. 9706.1 和 9706.202 的手写数值、模板差异和符号识别仍会产生人工项；
5. `report_ptr_report` 和 `report_diff` 仍属于禁用边界。

### 产品风险

1. 当前人工意见更多是复核记录和处理意见，仍需确认是否能完整形成正式的机器状态重算结果；
2. 历史 Run 较多，操作者需要区分最新结果、旧结果和规则版本；
3. 当前结果中的长文本仍可能需要展开“核对明细”和查看两侧 PDF 才能完成判断。

## 七、建议的下一步顺序

1. 统一 `PTR-P01` 规则版本，更新合同、能力目录、验收包、测试和文档；
2. 重新对 2948、0775、1539 做正式验收并保存新版本签字记录；
3. 优先人工标注 0775 的 48 条待确认，特别是表格项和可能存在真实要求变化的条款；

5. 接入受约束的 LLM 文本复核，只处理规则允许的文本人工队列；
6. 完成人工复核、状态重算、导出和审计闭环；
7. 完成验证后，将当前功能分支推送并创建独立 PR。
